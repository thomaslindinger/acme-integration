Integration Engineer Case: Acme

Expect it to take around 3–4 hours. We care about how you get to a solution more than the code itself.

The situation

You've just joined the Integration Team. Acme, a Nordic wholesaler, is one of our customers. Acme's customers email in orders and quote requests. Go Autonomous reads those emails, AI extracts the order data, and our integration layer transforms that data before it goes into Acme's ERP.

Customer email → GoA extraction (AI) → Integration layer: POST /transform → Acme ERP

Over the past week, several people at Acme have sent us requests. Your job is to work out what they actually need, decide how to handle each request, and implement your solution in the integration layer.

What you get

Start from the starter repository: github.com/thomaslindinger/acme-integration. Click Use this template to create your own private copy. It contains:

  • A minimal .NET Web API with a working POST /transform endpoint. Right now it returns the payload unchanged.
  • Models for the payload below, with snake_case JSON already set up.
  • A test project with one passing test.
  • reference/sales-areas.json: Acme's sales areas and what they mean.
  • samples/: a few example payloads.

You don't need to spend time on setup. Spend it on Acme.

The payload

This is what the extraction step sends to /transform. Your endpoint returns the same structure, transformed.

{
    "mail_id": "11111111-1111-1111-1111-111111111111",
    "iteration": "first",
    "intent": "request_simple_order",
    "area": {
        "name": "DK1"
    },
    "products": [
        {
            "line_number": 1,
            "product_number": { "id": "1", "value": "BP47283429" },
            "unit_price": { "id": "2", "value": "100" },
            "delivery_date": { "id": "3", "value": "2026-01-15" }
        },
        {
            "line_number": 2,
            "product_number": { "id": "4", "value": "BP3819238" },
            "unit_price": { "id": "5", "value": "200" },
            "delivery_date": { "id": "6", "value": "2026-01-15" }
        }
    ],
    "header": {
        "order_number": { "id": "7", "value": "4712371" },
        "account_id": { "id": "8", "value": "9000028128" }
    }
}

iteration

"first": the first time GoA processes the email.
"refresh": the order is sent again after someone in Acme Customer Service has reviewed or edited it in GoA.

intent

"request_simple_order": the customer wants to place an order.
"request_simple_quote": the customer wants a price quote.

Fields

Every field has a value and an id. Fields are never null: a missing value is an empty string "". If you add a new field, give it a new unique id (a GUID).

Requests from Acme

These came in by email. They're written the way customers actually write: they describe a problem, not a specification. Some are clearer than others. You decide what to do with each one, and that may not always mean writing code.

From: Mette Hansen, Customer Service Lead, Acme Nordic

Subject: Orders bouncing because of old delivery dates

Hi team,

A lot of our orders are being rejected by the ERP because the delivery date has already passed. Customers reuse old order forms or write "same as last time".

When a new order comes in with a date that's already passed, please just move it to the earliest date we can actually deliver. Our warehouse needs two working days to pick and pack.

Please don't touch the dates once my team has reviewed and updated an order. They know what they're doing.

Thanks,
Mette

From: Jonas Berg, Sales Operations, Acme Nordic

Subject: Freight on quotes

Hi,

Our sales reps keep forgetting to put freight on quotes, and we lose money every time. Could you make sure every quote request gets our standard freight line added? The item number is FREIGHT and it's 50 per quote.

Only on quotes, though. On orders, the ERP calculates freight itself. And obviously we don't want freight on there twice.

Best,
Jonas

From: Erik Lindqvist, IT, Acme Sverige

Subject: Item numbers for Sweden

Hej!

Our Swedish ERP was migrated last year, and it only stores item numbers as digits. The "BP" prefix our Danish colleagues use doesn't exist on our side. So for orders in our Swedish sales area, the item numbers need to be cleaned up before they reach us, or the lines fail.

This also applies after someone in Customer Service has corrected an order, because those go to the ERP too. We handle freight lines separately on our side.

/Erik

From: Lars Nielsen, Head of Sales, Acme Nordic

Subject: Sales rep on every order

Hi,

From now on, every order needs a responsible sales rep so the right person gets notified. Our staff directory has an API you can use. IT says the test environment is https://randomuser.me/api. It returns a person, and we need their email address.

Important: a customer should always get the same rep. Customers hate talking to someone new every time.

Also, we can't have orders getting stuck because of the directory. It's a bit flaky sometimes.

Regards,
Lars

What we'd like back

  1. Your implementation in the starter repo, for the requests you decide to solve in the integration layer.
  2. SOLUTION.md (about one page):
    • How you understood each request, and what you decided to do with it
    • The assumptions you made
    • Trade-offs, and what you would do differently in production
    • How you used AI tools: what you asked, and what you kept, changed or threw away
  3. QUESTIONS.md: the questions you would send back to Acme, or raise with the Engagement Manager, before going live.

Use AI tools

We use AI every day, and we want you to as well. Copilot, ChatGPT, Claude, whatever you prefer. AI can write code quickly, so code alone tells us little. What matters is understanding what the customer needs, choosing the right approach, and being able to explain and stand behind every line.

The follow-up interview

  • 15–20 minutes: you walk us through how you approached Acme's requests. No slides needed. Your repo and notes are enough.
  • Then: we ask questions, change a requirement or two, and talk through how you would handle it.

What we look at

Understanding the business

Did you get what Acme actually needs, including the parts they didn't spell out?

Judgement

What did you solve, what did you question, and what did you push back on?

Communication

Are your write-up and questions clear enough to send to a customer or an EM?

Solid code

Readable, testable, and robust when things go wrong. Neat beats clever.

Submission

Push your work to your private copy of the starter repository and add thomas@goautonomous.io as a collaborator at least one working day before your interview. If anything about the case is unclear, make an assumption and write it down. That's part of the exercise.
